# Problem statements and design decisions

## Problem statement (NN/g, Rosala 2021)
A short description of the one problem to solve. It scopes the work and gets buy in.

Three parts:
1. **Background**: who has the problem, what it is, why it happens.
2. **Affected people**: which users (and staff) and how.
3. **Impact**: what it costs if nothing changes. Put a number on it if possible.

Gather with the 5 Ws: who, what, where, when, why.

Rules: one core problem, no solution inside it, a few sentences, revise as research comes in.
Mistakes: list of unrelated problems, solution baked in, too long, frozen.

Opportunity version: gap between today and a desired future state.

**Template the skill uses**
> [User group] trying to [goal] currently [pain or workaround], because [cause]. This leads to [impact on users] and [impact on business, number].

## Design decision log
Every wireframe option ends with a decision log so choices are defensible later.

Keep each "why" tied to a named law, heuristic, or study in this vault. If no evidence exists, mark it "assumption" and add a test.
